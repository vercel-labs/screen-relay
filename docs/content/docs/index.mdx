screen-relay streams a Linux, macOS, or Windows desktop to your browser. Open the viewer link to see the screen and use it with your mouse and keyboard. An agent can control the same desktop from the `screen-relay` CLI, the Node SDK, or the HTTP and WebSocket API, taking screenshots and sending clicks, keys, and text.

## Quickstart

```sh
npm install -g screen-relay
screen-relay up
```

[Getting started](/docs/getting-started) explains each step.

## How it works

<Diagram name="architecture" title="How screen-relay connects the desktop, browser, and agent" aspectRatio="720 / 288" />

The engine captures the screen, encodes it as H.264 video, and streams it to the viewer. The viewer, or an agent over HTTP or WebSocket, sends input back. To see how the stream adapts to a slow link, read [How streaming works](/docs/how-streaming-works).

## What works where

| Platform | Backend | Start a desktop | Details |
| --- | --- | --- | --- |
| Linux | `x11` (default) or `wayland` | `screen-relay up -d` | [Linux](/docs/linux) |
| macOS 12.3 or later | `macos` | `screen-relay up -d` | [macOS](/docs/macos) |
| Windows 10 or later, x64 | `windows` | `screen-relay up -d` | [Windows](/docs/windows) |

## Limits

- Audio, IME, and relative pointer are not supported. The clipboard carries text only.
- Three capture failures in a row end the session. `screen-relay logs` shows why.

Control, desktop size, and access rules are covered in [CLI reference](/docs/cli), [Configuration](/docs/configuration), and [Remote access](/docs/remote-access).
