On Windows, screen-relay attaches to the desktop of the signed-in user. It starts no virtual display and no desktop. The `windows` backend is the only backend on Windows.

## Build the engine

- Windows 10 or later, on x64.
- Node 22 or newer, with npm.
- A user signed in at the PC's own screen. Start screen-relay from a terminal in that session.

## Install

Install the CLI with `npm install -g screen-relay`, as in [Getting started](/docs/getting-started#install-screen-relay). Then set up the PC:

```sh
screen-relay install
```

Setup uses MSYS2 at `C:\msys64`. If that folder does not exist, setup creates it with full control for SYSTEM, Administrators, and your account, and read and execute access for Users. It then installs MSYS2 with winget (`winget install MSYS2.MSYS2`). Setup needs permission to create `C:\msys64`; if your account cannot, run the command from an elevated terminal. Without winget, setup stops and asks you to install MSYS2 manually. Setup does not change the access rules of an existing installation; it only adds the packages it needs with pacman. It uses an existing `C:\msys64` only if it passes the access checks; if it does not, setup stops. Do not change or install over an existing tree.

### Install MSYS2 manually

Use an elevated PowerShell window opened as the same Windows account that will run screen-relay. This procedure creates a new, empty `C:\msys64`. If that path already exists, stop; do not change its access rules or install over it.

```powershell
$ErrorActionPreference = 'Stop'
$root = 'C:\msys64'
if (Test-Path -LiteralPath $root) {
  throw 'C:\msys64 already exists. This procedure requires a new directory.'
}
New-Item -ItemType Directory -Path $root -ErrorAction Stop | Out-Null
$sid = [System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value
if (-not $sid) {
  throw 'Could not determine the current Windows account SID.'
}
& "$env:SystemRoot\System32\icacls.exe" $root /inheritance:r /grant:r `
  '*S-1-5-18:(OI)(CI)F' `
  '*S-1-5-32-544:(OI)(CI)F' `
  "*$($sid):(OI)(CI)F" `
  '*S-1-5-32-545:(OI)(CI)RX'
if ($LASTEXITCODE -ne 0) {
  throw 'icacls failed. Stop and do not run the MSYS2 installer.'
}
```

These rules give full control to SYSTEM, Administrators, and the current account, and read and execute access to Users. The rules inherit to files and subdirectories. If the command throws an error or `icacls` returns a nonzero exit code, stop and do not continue with the installer. Download the current GUI installer from the official [MSYS2 installer page](https://www.msys2.org/docs/installer/). From the directory containing the downloaded file, run the installer in install mode with `C:/msys64` as the root, replacing the filename if needed:

```powershell
.\msys2-x86_64-latest.exe in --confirm-command --accept-messages --root C:/msys64
```

After installation, run `screen-relay install` again from a terminal in the signed-in user's desktop session.

Setup then installs `make`, `diffutils`, `mingw-w64-ucrt-x86_64-gcc`, `mingw-w64-ucrt-x86_64-pkgconf`, `mingw-w64-ucrt-x86_64-libwebsockets`, and `mingw-w64-ucrt-x86_64-x264` with pacman, and builds the engine.

At a terminal, setup asks before it installs anything. Anywhere else, pass `--yes`. Setup is safe to repeat. On Windows, `--backend` accepts only `windows`.

## Start a session

Run this in a terminal on the signed-in user's desktop:

```sh
screen-relay up -d
```

`up` attaches to that desktop. It prints the viewer link, and the link always carries a token, as on a Mac. A PC that is not set up is set up first. Open the viewer link in a browser. For a viewer on another machine, see [Remote access](/docs/remote-access). Stop the session with `screen-relay down`.

Over SSH or from a service session, `install` works and `up` fails. The error carries the engine's message, which is one of these:

- `No display is attached to this session; start relay in the signed-in user's desktop session`
- `Desktop Duplication is unavailable; start relay in the signed-in user's desktop session`

To start an app on the signed-in desktop, run:

```sh
screen-relay run -- APP
```

APP must be an `.exe` program. A `.cmd` or `.bat` file is started through `cmd /c`, so run it as `screen-relay run -- cmd /c FILE.cmd`.

`--restart` is not supported on Windows. `screen-relay down` leaves apps started with `run` running.

### Choose a display

screen-relay captures the primary display by default. To capture another, pass its name, such as `'\\.\DISPLAY2'`:

```sh
screen-relay up -d --output '\\.\DISPLAY2'
```

Quote the name so the shell keeps its backslashes. An unknown name lists the attached displays.

`--display` is not supported on Windows. `display.resolution` is ignored, and screen-relay prints a warning if your configuration sets it.

## What you will notice

- Text is typed with the keyboard layout of the foreground window. Characters that layout cannot type are sent as Unicode input.
- If the display's size or position changes, the stream stops with `The display changed from WxH to WxH or moved; restart relay to stream it`. Run `screen-relay up` again.

## Check the machine

```sh
screen-relay doctor
```

The checks cover the Windows version, MSYS2, the engine, and whether the command runs in a desktop session. The MSYS2 check fails when setup cannot verify the installation's owner and write rules.

## Remote access

Remote access works as it does on Linux. See [Remote access](/docs/remote-access).

## Limits

- The engine captures one display at a time: the primary display unless you pass `--output`. A display wider or taller than 16384 pixels is halved until it fits. The streamed size must be 320 to 16384 pixels wide and 240 to 16384 pixels high, with even dimensions.
- Windows refuses input to elevated (administrator) windows, and the engine reports that input as not applied.
- Not supported in this version: running `up` or `run` over SSH, a PC with nobody signed in, Remote Desktop sessions, Windows on ARM, and MSYS2 at a root other than `C:\msys64`.
